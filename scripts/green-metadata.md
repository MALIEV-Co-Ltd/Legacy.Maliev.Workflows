# Selected green metadata contract

The optional `green_contract` on `run_handoff` carries an explicitly supplied historical artifact, modern application/container, and namespace mapping. The contract preserves the case-sensitive 23-artifact source inventory. A valid mapping does not establish owner approval, provider identity, cluster admission, or a live deployment. There is no default modern mapping and no physical adapter.

The mapped SNAPSHOT must return `deployment.greenMetadata` with exactly `containerNames`, `unsafeFields`, `environment`, `containerMetadata`, and `podMetadata`. This is a selected-field receipt, not a whole PodSpec. The producer must actually observe these fields and the unsafe-shape evidence. The library cannot establish the truth of an arbitrary injected receipt.

Before VERIFY_SOURCE or VERIFY_IMAGE, the plan rejects multiple/foreign containers, unsafe init containers/commands/arguments/mounts/volumes, unknown literal environment values, duplicate environment names, and unknown reference/probe shapes. Known Boolean flags become lowercase strings; singleton environment, port, envFrom, imagePullSecret and toleration arrays remain arrays. Allowed configuration references remain detached and structurally unchanged. Both readiness and liveness probes are required; missing/null startup is optional. One HTTP/TCP/gRPC handler is allowed; exec, headers, multiple handlers, unknown keys, missing ports, and Boolean numeric values reject. Source Material mapping additionally requires the separately admitted startup contract and read-only startup proof. No Material or Catalog endpoint default is supplied.

CREATE_GREEN receives `greenMetadataPlan`: namespace plus selected pod/container metadata, immutable image digest, standby flag, 60-second drain hook, and 90-second termination grace. This is a metadata plan, not a complete Kubernetes manifest. Actual CREATE_GREEN and VERIFY_GREEN receipts must return the exact stored plan. Green is proved again after public health and immediately before canonical mutation. VERIFY_FALLBACK must independently prove the same stored metadata. Type-sensitive comparison rejects Boolean/integer substitution. Every pre-mutation current read must retain the admitted baseline metadata, including selector rollback; post-mutation failure recovery retains the existing canonical identity-only fallback rule and independently proves owned green.

Default callers omit the option and retain their existing request shapes. Unrelated applications receive no metadata injection. Direct-file loaders retain trusted sibling loading without PYTHONPATH changes. There is no canonical container-metadata replacement: only the separately approved startup option may affect canonical probe requests. Existing UID, image, replica, Service/CAS, source/image, capacity, process-route and rollback fences remain applicable.

The mapped MUTATE_CANONICAL request also binds the owned `greenDeploymentUid`, `expectedGreenMetadataPlan`, `expectedCanonicalMetadata`, `expectedCanonicalReplicas`, and `expectedGreenReplicas`. The injected producer must enforce these preconditions with the existing UID/image/Service conditions before applying its canonical change. Independent stateful producer tests alter stored green or canonical metadata, either UID, replica count, or Service identity inside the mutation callback and reject without image mutation. This does not attest atomicity of an arbitrary real callback or deployment API; physical adapters must implement their own reviewed concurrency mechanism.

Source provenance is retained individually: 77dad40455484f18578bd073ef121367d299a9d5 supplies singleton-array/Boolean behavior; 3fd301fe85cd8ca61434569eccb67a369eda47a4 supplies optional-probe and selected metadata admission; eb11c81a6c759e1d4bcd1a1b3b28dc5f30cc02cb supplies separately approved startup protection. The thirteen-source review retains all127 changed paths and mixed owners. The direct safe-rollout first-migration pre-build/push rule from 19ff7581e54801545238edb16828ad303ae5c5e6 remains a separate caller obligation: initial protected handoff and image-only preparation intentionally have different admission paths. This metadata slice does not certify either physical path, provider credentials, registry publication, data, infrastructure, service adoption, or whole-source closure.

Input and readback JSON-compatible values are bounded to16KiB,1024 nodes,16 levels,128 entries per array/object, and bounded strings before serialization. Malformed Unicode and nonfinite/non-JSON values reject with fixed diagnostics. These deliberate target rules are stricter than some legacy PowerShell coercions. They do not establish byte-equivalence or Kubernetes schema certification. Draft Python diagnostics and unexecuted native bridge code are separate evidence; native build/full/hosted acceptance must be recorded before publication.
