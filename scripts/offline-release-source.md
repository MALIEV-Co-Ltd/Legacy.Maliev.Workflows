# Read-only release source guard

Dot-source `Assert-OfflineReleaseSource.ps1`. Call `Assert-OfflineReleaseSource -RepositoryRoot <isolated-checkout-root> -ExpectedSourceCommit <lowercase-full-SHA> -ApprovedSourceRepository <exact-origin-URL>`. The paired Python module is `offline_release_source.py`; consumers pin both committed files and may supply its exact path with `SourceGuardModulePath`.

The guard observes the actual Git checkout root, full HEAD, tracked/staged/untracked status, exact single origin URL, and exact single `refs/heads/main` remote SHA. It repeats local HEAD/status/origin reads after transport. Git reads disable optional index locks, fsmonitor and untracked cache. All ambient `GIT_*` selectors, object/index paths, config injection and traces are removed only from the child environment. Native stdout and stderr are each limited to 16 KiB before decoding, with a ten-second total observation budget and opaque diagnostics; bounded positive native exit codes are preserved. The PowerShell bridge has a twenty-second outer budget and withholds raw output.

Production origin inputs must be exact HTTPS URLs under `github.com/MALIEV-Co-Ltd/` for `maliev-web` or `Legacy.Maliev.<letters>`, ending in `.git`. No credentials, login or credential creation are supplied. An explicit `AllowFixtureOrigin` switch permits `file:///` isolated bare-origin fixtures; those receipts say `isolated-fixture-origin`, never a cryptographically authenticated production repository.

The seven returned fields are `schemaVersion=offline-release-source/v1`, `sourceCommit`, `repositoryIdentity`, `cleanObserved=true`, `remoteMainObserved=true`, `deploymentAllowed=false`, and `liveAccepted=false`. The Python CLI takes one bounded 8 KiB JSON object on stdin with exactly `repositoryRoot`, `expectedCommit`, `expectedOrigin`, and Boolean `allowFixtureOrigin`, and emits one receipt or an opaque failure object. It invokes only Git reads: no fetch, clean, reset, checkout, build, publication, cloud, data or resource mutation adapter exists.

The actual PowerShell caller bridge concurrently drains the Python process's stdout and stderr within its twenty-second budget, including asynchronous stdin writing. Receipt stdout is bounded to 2 KiB before strict UTF-8 decoding; stderr is bounded to 16 KiB and discarded without decoding, printing or joining it into the receipt. A zero exit with bounded warning stderr may admit only a valid seven-field receipt. Nonzero native exits, malformed or empty stdout, oversized streams and an unresponsive child reject with opaque diagnostics; an observed nonzero exit remains available in exception `Data['ExitCode']`. The stream tests invoke this actual bridge with deterministic local Python children, while the retained source tests separately observe real isolated Git checkouts and bare origins. Synthetic stream receipts do not establish source authenticity.

This bounded caller behavior adapts the stdout/stderr separation and safe exit semantics from `c9cc1f319767d9318158e7888cda569489f01468` at the actual source-observation consumer. It supplies no registry/deployment CLI adapter and does not close the whole historical source. FileService pins this PowerShell script separately from the Python module and image-plan producer; adoption of changed bridge bytes requires an exact reviewed consumer pin and paired tests.

The File consumer must run three independent observations: before its IAM reader, immediately before its controlled image builder, and after that builder before returning the image-only plan. A callback can change the checkout, so a successful earlier receipt must not be reused. These reads do not atomically lock a checkout or remote main; state can change after an observation. They do not establish signed source provenance, build/image authenticity, live IAM or deployment acceptance.

This carries a bounded source preflight portion of original `1ec9ef70db2010936964b51a741bf282133298fa` (parent `f14d3ef9c294783a34d1196050f51f682aab8316`) and `44b1420029793e6acd914582364b9d38c3944d78` (parent `c3450c9d9a75f04b32eeed91d05d95b9f7a2c449`), paths `tools/diagnostics/Invoke-LegacyApplicationOnlyRelease.ps1` and its tests. It does not restore obsolete resource helpers or accept native release executors, live identity, rollout, original YAML or whole source SHAs.
