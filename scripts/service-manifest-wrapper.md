# Offline historical Service wrapper boundary

Call `run_service_wrapper(application, source_commit, manifest, injected_tool)` from `service_manifest_wrapper.py`. It has no CLI, native subprocess, file writer, credential reader or provider adapter. The single injected operation is `APPLY_SERVICE_MANIFEST`. Its request contains the exact application, lowercase full source commit, SHA-256 of canonical JSON, and a separately copied Service document. Caller input is preserved, and success rejects mutation of the dispatched request.

This carries the Service-only split from original `3a393215d883fa35e1461f69c876bf2ead7ce36e`, paths `Maliev.UploadService.Api/deploy-service.ps1`, `Maliev.PdfService.Api/deploy-service.ps1`, `Maliev.EmailService.Api/deploy-service.ps1` and their `service.yaml` files. Their original Services use namespace `maliev`, names `maliev-uploadservice-api`, `maliev-pdfservice-api`, `maliev-emailservice-api`, and corresponding `run` selectors. Those identities remain exact in this bounded historical contract. Deployment, Ingress, List and embedded resource lists are rejected before dispatch. This is not complete Kubernetes schema validation or authorization to apply the resource.

The regression suite independently pins the full committed canonical-LF bytes of each fixture, including its source/checkpoint paths, hashes and every manifest value. Only checkout CRLF line endings are normalized. Mutation controls verify refusal of provenance and non-identity payload drift. The caller workflow compiles both Python modules and runs the complete wrapper suite in a finite job; the required `validate / validate` job depends on that success. This reusable policy and its regression fixtures belong to Workflows. Migration registries, inventory generators and acceptance reports remain outside this repository.

The original checkpoint `135e526d0dab85c415b3afdcefd7b70fe2c82e2f` wrappers check `LASTEXITCODE`, propagate nonzero status, and return zero on success. The injected result must contain exactly `exitCode` and `receipt`. A nonnegative integer status through 2147483647 is accepted; a nonzero status raises the opaque `ServiceWrapperFailure` carrying that same code. A zero status requires a receipt containing exactly the matching `sourceCommit` and `manifestSha256`. Exceptions, including callback-supplied public failure objects, normalize to opaque exit 1. All request and result JSON is bounded to 16 KiB, rejects nonfinite values, non-string keys and non-JSON containers, and is depth-limited.

Receipts retain `deploymentAllowed=false`, `runtimeAccepted=false` and `consumerAdoptionAccepted=false`. Callback receipts are supplied claims. Source/image authenticity, signed manifests, live resource observation, WIF, namespace adaptation to `maliev-legacy`, actual command execution, child-process cleanup, Service/Ingress runtime parity and canonical owner adoption remain separate obligations. No later ApplicationOnly helper dependency is applied retroactively to these wrappers. Original pauses are omitted because this policy performs no interactive native operation.

## Canonical dormant Service admission

`verify_canonical_service_projection(application, source_commit, services, active_identities)` checks the separately rendered canonical projection. It invokes no callback or native command and cannot apply a resource. The caller supplies only Service documents from the target projection and minimal `kind/name/namespace` identities from the active environment. Each JSON input remains bounded to 16 KiB; no deployment, Secret or environment payload is returned. The full source commit is a caller assertion, not authenticated provenance.

File currently has no Service lane in its recording producer, and Document has a secret-only projection. Both require an empty Service list. Notification requires exactly its `legacy-maliev-notification-service` Service in `maliev-legacy`, with the canonical name/environment labels and selector, `ClusterIP` exposure, and its single TCP `http` port 8080 targeting the named `http` container port. Deployment, Ingress, duplicate Services, external exposure, unknown configuration, foreign identities and ambiguous ports reject. Active resources with an owned canonical name in `maliev-legacy` reject dormant admission. Other namespaces and cluster-scoped identities do not establish target adoption.

This adapts the Service separation obligation of original `3a393215d883fa35e1461f69c876bf2ead7ce36e` (parent `e2ae2bd3c4edac22b04ef96fc1041da34380e9ea`) and the scoped wrapper status behavior retained at checkpoint `135e526d0dab85c415b3afdcefd7b70fe2c82e2f`. The canonical internal Service is an explicit GitOps security adaptation, not original NodePort parity. The source-bound regression fixture comes from local rendering of the existing dormant projections; independent fixture pins and negative controls gate required CI. GitOps consumer integration remains separate. This does not establish active capacity, permissions, WIF, workload resources, release execution, runtime parity, canonical owner adoption or whole-source closure.
